PATCH FOCUS
Parser and workflow regression hardening.

ROOT CAUSES FOUND
1. Dismantle/dismount work descriptions were not classified as service-only rows.
2. The old service gate could also discard a real equipment row when the same row contained bundled installation/dismantling/commissioning text.
3. Product identity correction could select an unrelated model token elsewhere on the invoice and overwrite a credible row SKU/model.
4. Version/workflow regression checks verified symbol presence but did not enforce critical parser behavior.

IMPLEMENTED
- Added dismantle/dismount/de-mount/removal-of-existing service patterns.
- Service-only rows remain excluded even when they mention a model, when the primary row is a work action.
- Verified equipment rows with credible model + equipment identity survive bundled service text.
- Product candidates now require row relevance before replacing an unsupported SKU/model.
- A directly printed credible row model is preserved instead of being overwritten by unrelated invoice tokens.
- Added runRegressionChecks() to v7033-core.js.
- Loader now blocks startup if core version, upcoming-version separation, or behavioral regression suite fails.
